# EdgeShield GitHub-maintained rules / 边缘盾规则目录

Scheduled GitHub Actions is ON by default, every six hours on main. Edits to the maintained inputs also trigger the same workflow. No Cloudflare Worker Cron or scheduled() handler is needed.

- sources.yaml: explicit allowlist, approved license, service scope and autoApply controls. Local curated.json is the **safe starter**, not a general upstream security feed.
- curated.json: 16 narrowly scoped, executable Shield IR block rules for exposed secret/config paths, reconnaissance endpoints, high-confidence query probes and a malicious header marker. These are heuristic protections, not complete WAF coverage.
- baseline.json and regression.json: required baseline and independent attack/legitimate samples.
- active.json: generated by the Action ONLY if all source and full merged regressions pass; changes stay in GitHub.
- inventory.json: add exact installed origin software versions; empty by default because a Worker cannot know private origin versions.
- cve-candidates.json: OSV advisories for EdgeShield's actual installed npm dependencies and operator-supplied origin inventory.
- emergency-paths.json: optional preapproved full-feature isolation paths. Default empty; no CVE-driven blocking occurs automatically.

External upstream rule feeds: configure a vetted HTTPS location in sources.yaml, an accurate allowed license, and regression fixtures that independently cover every rule. SecLang/CRS and ambiguous conversions cannot be silently installed. A failing source/test/CVE request leaves committed files unchanged.

Security: The Action commits active.json, cve-candidates.json and versioned, non-executable upstream/crs archives under rules/. It never edits Cloudflare POLICY, routes, origin, Keyless SSL or DNS. Deploy new policies through a separate operator-approved process. OSV risk reports are candidates, not proof of exploitation or a vendor fix. Temporary isolation requires fresh evidence, bounded TTL, approval and rollback.

中文：默认每 6 小时自动更新 GitHub 仓库 /rules 下的已验证生成文件。仅允许事先批准的规则源与测试；云端 Worker 不参与定时同步，不自动发布线上规则。当前内置 16 条有针对性的边界防护规则；要覆盖更多攻击类型，需要审核并转换上游来源，不能将原始 CRS 文件直接当成可执行规则。

## Automatically archived official OWASP CRS upstream / OWASP 原始上游归档

`scripts/sync-upstream-rules.mjs` retrieves the official latest v4.x OWASP CRS release directly from the verified `coreruleset/coreruleset` repository. It archives seven categories of real SecLang rules under `upstream/crs/`, with their Apache-2.0 LICENSE, source tag, per-file SHA-256 digests, and rule counts.

**Important:** These are original ModSecurity/SecLang rules. They are **not** compiled, compatible, or active in the EdgeShield runtime. Do not treat the archive as fully deployed CRS. Automatic conversion would require faithfully preserving transformations, anomaly scoring, phases and audit semantics; unsupported rules must be rejected rather than silently imported.

The executable EdgeShield policy comes from `curated.json` (a focused set of high-confidence protections against sensitive-file scanning and obvious query/header probes) plus explicitly approved and independently regression-tested Shield IR sources. Its narrow query-parameter coverage is not equivalent to generic SQLi/XSS WAF coverage. The CI validates every source and every active rule before committing `active.json`.

The action updates the archive and policy in GitHub only; independent deployment approval is required before production enforcement.
